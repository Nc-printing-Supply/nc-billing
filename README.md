# NC Printing Supply — ระบบออกเอกสารและจัดการบิล

ระบบออกใบเสนอราคา ใบแจ้งหนี้ ใบเสร็จรับเงิน และใบกำกับภาษี สำหรับ
**ห้างหุ้นส่วนจำกัด เอ็นซี ปริ้นติ้ง ซัพพลาย** (งานพิมพ์ สกรีนเสื้อผ้า สติกเกอร์ และป้ายโฆษณา)

Next.js 15 · TypeScript · Tailwind CSS 4 · PostgreSQL 16 · ฟอนต์ Sarabun (ฝังในโปรเจกต์ ไม่ต้องโหลดจากเน็ต)

## ติดตั้งและเปิดใช้งาน

ต้องมี Node.js 20+ และ PostgreSQL 14+ (หรือ Docker)

```bash
npm install
cp .env.example .env          # แก้ DATABASE_URL / รหัสผ่านผู้ดูแลตามต้องการ
docker compose up -d db       # ถ้ายังไม่มี PostgreSQL
npm run db:migrate            # สร้างตาราง
npm run db:seed               # บัญชีผู้ดูแล + ข้อมูลตัวอย่าง (สมมติ)
npm run build && npm start    # หรือ npm run dev ระหว่างพัฒนา
```

เปิด http://localhost:3000 แล้วเข้าสู่ระบบด้วย `SEED_ADMIN_EMAIL` / `SEED_ADMIN_PASSWORD` ใน `.env`
(ค่าเริ่มต้น `admin@example.com` / `ChangeMe123!`). **เปลี่ยนรหัสผ่านทันที** ที่ ตั้งค่า → บัญชีผู้ใช้

จากนั้นไปที่ **ตั้งค่า** เพื่อกรอกที่อยู่ เลขประจำตัวผู้เสียภาษี โลโก้ และบัญชีธนาคาร (ระบบไม่ได้กรอกข้อมูลเหล่านี้ให้)

| คำสั่ง | ใช้ทำอะไร |
|---|---|
| `npm test` | Unit test การคำนวณเงิน/VAT/ปัดเศษ/ตัวอักษรบาท |
| `npm run test:e2e` | ทดสอบขั้นตอนหลักผ่านเบราว์เซอร์จริง (ต้องเปิดเซิร์ฟเวอร์ไว้) ภาพหน้าจอ+PDF อยู่ใน `test-output/` |
| `npm run db:reset` | **ลบข้อมูลทั้งหมด** แล้วสร้างข้อมูลตัวอย่างใหม่ |

### การสร้าง PDF
- ปุ่ม **PDF** สร้างไฟล์ A4 ฝั่งเซิร์ฟเวอร์ด้วย Chromium (ตั้ง `CHROMIUM_PATH` ใน `.env`) — ใช้หน้าแม่แบบเดียวกับหน้าจอ ยอดเงินและภาษาไทยจึงตรงกัน
- ถ้าเซิร์ฟเวอร์ไม่มี Chromium ปุ่ม PDF จะแจ้งข้อความ ให้ใช้ปุ่ม **พิมพ์** → "บันทึกเป็น PDF" ของเบราว์เซอร์แทน (ผลลัพธ์เหมือนกัน)

## Deploy บน Render

โปรเจกต์มี `Dockerfile` (รวม Chromium สำหรับปุ่ม PDF) และ `render.yaml` (เว็บ + PostgreSQL) ให้แล้ว

1. นำโค้ดขึ้น GitHub repository (private ได้)
2. ที่ https://dashboard.render.com กด **New → Blueprint** แล้วเลือก repository นี้
3. Render จะถามค่า 2 ตัว: `SEED_ADMIN_EMAIL` (อีเมลผู้ดูแล) และ `SEED_ADMIN_PASSWORD` (อย่างน้อย 8 ตัวอักษร)
4. กด **Apply** แล้วรอ build ประมาณ 5–10 นาที จะได้ URL แบบ `https://nc-printing-billing.onrender.com`

ทุกครั้งที่เริ่มเซิร์ฟเวอร์ ระบบจะรัน migration ให้เอง และสร้างบัญชีผู้ดูแลเฉพาะครั้งแรก (ไม่ใส่ข้อมูลตัวอย่าง เพราะตั้ง `SEED_DEMO_DATA=false`)

ข้อจำกัดของแผนฟรีของ Render
- เว็บจะ "หลับ" เมื่อไม่มีคนใช้ 15 นาที เปิดครั้งแรกหลังจากนั้นรอประมาณ 30–60 วินาที
- ฐานข้อมูลฟรีหมดอายุหลัง 30 วัน — ก่อนครบต้องอัปเกรด (เริ่มประมาณ US$7/เดือน) ไม่เช่นนั้นข้อมูลจะถูกลบ
- หน่วยความจำ 512 MB: สร้าง PDF ได้ แต่ถ้าหลายคนกดพร้อมกันอาจช้า ถ้าใช้งานจริงแนะนำแผน Starter

## โครงสร้างโค้ด

```
src/lib/          ตรรกะล้วน ใช้ร่วมกันทั้งหน้าจอและเซิร์ฟเวอร์
  money.ts          เงินเป็น "สตางค์" (จำนวนเต็ม) จำนวนเป็นหน่วย 1/1000 อัตราภาษีเป็น basis point
  calc.ts           คำนวณยอดรายการ ส่วนลด VAT (ไม่คิด/รวม/แยก) มัดจำ — ปัดเศษ half-up แบบ BigInt
  bahttext.ts       จำนวนเงินเป็นตัวอักษรภาษาไทย
  schemas.ts        ตรวจสอบข้อมูล (zod) พร้อมข้อความผิดพลาดภาษาไทย
  domain.ts         ประเภทเอกสาร สถานะ รูปแบบเลขที่ วันที่ พ.ศ.
src/server/       เข้าถึงฐานข้อมูล + สิทธิ์ (ไม่ถูกส่งไปเบราว์เซอร์)
  auth.ts           session cookie (httpOnly) เก็บ hash ของ token ใน DB, bcrypt
  repo/*.ts         SQL ของลูกค้า สินค้า เอกสาร การรับชำระ dashboard
src/app/api/      REST API — ทุก endpoint ตรวจ session ฝั่งเซิร์ฟเวอร์
src/app/app/      หน้าจอระบบ (/app)
src/app/print/    หน้า A4 สำหรับพิมพ์/สร้าง PDF
db/*.sql          migration
```

หลักการสำคัญ
- **ยอดเงินคำนวณซ้ำที่เซิร์ฟเวอร์ทุกครั้ง** ด้วยฟังก์ชันเดียวกับหน้าจอ ไม่เชื่อยอดที่ส่งมาจากเบราว์เซอร์
- **เลขที่เอกสารไม่ซ้ำ**: ออกเลขใน transaction พร้อม lock แถวลำดับ + unique constraint `(doc_type, doc_no)`; เลขที่กำหนดเองก็ถูกตรวจ; เอกสารที่ออกแล้วลบไม่ได้ (ใช้ "ยกเลิก") เพื่อไม่ให้เลขกระโดด/ถูกนำกลับมาใช้
- **การเชื่อมเอกสาร**: ใบเสนอราคา → ใบแจ้งหนี้ / ใบกำกับภาษี / ใบเสร็จ, ใบแจ้งหนี้ → ใบกำกับภาษี, การรับชำระแต่ละครั้ง → ใบเสร็จอัตโนมัติ เก็บ `source_id` เพื่อแสดง "เอกสารที่เกี่ยวข้อง"
- **มัดจำ**: รับมัดจำที่ใบเสนอราคา แล้วยอดจะถูกหักให้อัตโนมัติเมื่อแปลงเป็นใบแจ้งหนี้; รับชำระบางส่วนได้หลายครั้ง ระบบคำนวณคงเหลือและกันรับเกินยอด
- **ยอดขายบน Dashboard** นับเฉพาะเอกสารที่เป็น "ตัวขาย" (ใบแจ้งหนี้ หรือใบกำกับภาษี/ใบเสร็จที่ออกโดยไม่มีใบแจ้งหนี้) เพื่อไม่ให้นับซ้ำ

## ข้อจำกัดและสิ่งที่ยังไม่ได้ทำ
- **หน้าตายังไม่ได้เทียบกับเว็บต้นแบบ** — สภาพแวดล้อมที่พัฒนาเข้าเว็บต้นแบบไม่ได้ (network policy ปฏิเสธ) สีและขนาดรวมไว้ที่ `src/app/globals.css` (`@theme`) เพื่อปรับให้ตรงเมื่อได้ภาพหน้าจอ
- ยังไม่มีหน้าจัดการผู้ใช้หลายคน (มีสิทธิ์ admin/staff ในฐานข้อมูลแล้ว; staff แก้หน้าตั้งค่าไม่ได้) — เพิ่มผู้ใช้ได้ทาง SQL
- ยังไม่มี: ภาษีหัก ณ ที่จ่าย, ส่งอีเมลเอกสาร, ใบลดหนี้/เพิ่มหนี้, export Excel, จำกัดจำนวนครั้ง login ผิด (ควรเพิ่มก่อนเปิดให้เข้าจากอินเทอร์เน็ต)
- โลโก้เก็บเป็น data URL ในฐานข้อมูล (ย่อให้อัตโนมัติ) — เหมาะกับไฟล์เล็ก
- ใช้งานจริงบนอินเทอร์เน็ตต้องใช้ HTTPS และตั้งรหัสผ่านฐานข้อมูลใหม่
